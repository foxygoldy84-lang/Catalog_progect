# Проект «Каталог товаров» (Django)

Учебный проект на Django: каталог товаров, страница контактов и блог для улучшения SEO.

## Домашнее задание 26: Django Forms, валидация и CRUD продуктов

В рамках домашней работы реализован полный CRUD для модели `Product` на основе `django.forms` и добавлена валидация данных.

### Выполненные задачи:
1. **CRUD продуктов**: добавлены страницы редактирования и удаления товара, создание уже было реализовано. Формы создания и редактирования используют общий `ProductForm`.
2. **Запрещённые слова**: форма проверяет название и описание продукта на слова «казино», «криптовалюта», «крипта», «биржа», «дешево», «бесплатно», «обман», «полиция», «радар» без учёта регистра.
3. **Валидация цены**: метод `clean_price` не разрешает сохранять товар с отрицательной ценой.
4. **Стилизация формы**: все CSS-классы и атрибуты полей задаются в методе `ProductForm.__init__`, поэтому формы соответствуют стилю Bootstrap-интерфейса.
5. **Дополнительное задание**: метод `clean_image` проверяет, что загружено изображение формата JPEG или PNG размером не более 5 МБ.
6. **Тесты**: добавлены проверки запрещённых слов, отрицательной цены, форматов и размера изображения, стилизации формы, а также редактирования и удаления товара.

## Домашнее задание 25: FBV и CBV

В рамках домашней работы контроллеры проекта переведены с FBV на CBV, а также добавлено приложение блога.

### Выполненные задачи:
1. **Переход на CBV**: `HomeView` (`ListView`), `ProductDetailView` (`DetailView`), `ContactsView` (`TemplateView`) и `ProductCreateView` (`CreateView`). Маршруты переведены на `.as_view()`.
2. **Приложение `blog`**: создана модель `BlogPost` с заголовком, содержанием, превью, датой создания, признаком публикации и количеством просмотров. Реализован полный CRUD на CBV.
3. **Логика блога**: при открытии статьи увеличивается счётчик просмотров, в списке показываются только опубликованные записи, после редактирования выполняется переход на просмотр статьи.
4. **Дополнительное задание**: при достижении 100 просмотров отправляется письмо-поздравление. По умолчанию используется консольный email-backend, настройки для реальной почты находятся в `.env`.
5. **Тесты**: добавлены проверки CRUD блога, фильтрации публикаций, счётчика просмотров, редиректа после редактирования и отправки письма.

### Запуск проекта:
```bash
poetry install
poetry run python manage.py migrate
poetry run python manage.py runserver
```

## Предыдущая домашняя работа: Django ORM и PostgreSQL

В рамках данной домашней работы проект переведён на использование полноценной реляционной СУБД и настроена работа с объектно-реляционным отображением (Django ORM).

### Выполненные задачи:
1. **Подключение PostgreSQL**: База данных переведена с SQLite на PostgreSQL. Настройки подключения вынесены в безопасные переменные окружения.
2. **Проектирование моделей**: Созданы модели `Category` (Категории) и `Product` (Продукты), а также дополнительная модель `ContactInfo` для динамического вывода контактов компании. Настроены связи `ForeignKey` и автозаполнение дат.
3. **Административная панель**: Модели зарегистрированы в админке. Настроена фильтрация продуктов по категориям и текстовый поиск по названию/описанию.
4. **Фикстуры и автоматизация**: Данные выгружены в JSON-формате (с поддержкой кодировки UTF-8). Реализована кастомная команда управления для автоматической очистки и наполнения базы данных.
5. **Интерактивный Shell**: В зависимости проекта добавлена библиотека `ipython` для удобной отладки в консоли.

### Запуск кастомной команды наполнения базы данных:
```bash
poetry run python manage.py fill_db
```
